# 恰好在 Rainy75 V2 发布之际聊聊 V1 以及 WOB 的售后 - 电脑讨论(新) 

> LZ 大约在 2 年前购入一把擦边客制化的量产铝机械键盘 rainy75，刚好 v2 版本最近发售，决定以为一个基础需求聊聊一些玩小众键盘可能遇到的坑，V1 从质感来说尚可，但功能性、客服支持确实需要避雷。

## 原因探索

需求场景：需要在同一把键盘上利用切换连接功能，分别实现对 windows 台式和 mbp 的控制。兼顾 windows 游戏 / mac 干活的场景。实际连接方式为:
- 有线 --> Windows 台式
- 蓝牙 --> mac

实际表现为：键盘打开电池供电，Windows 开机状态下，有线 / 2.4g / 蓝牙切换正常。Windows 关机状态下，Fn + Tab 无法完成连接模式切换，必须拔掉 Type-C 连接线才能重新激活该功能。以铝坨坨的动不动 5 斤的重量，实际体验极差。

也因为这个原因这把键盘被我一度打入冷宫，对比一把手边百元出头的迈从，塑料外壳虽然不如铝，但是通过物理按键模式切换提供的确定性极强。

事情的转机在这两天，V2的商单推送透过算法精准地推送到我这个老用户。勾起我重新折腾的兴趣。在 AI 的分析和建议下，关闭 usb 休眠主板供电后（AORUS BIOS Advanced Mode Settings → Platform Power → ErP switch to **enable** ）后，重新尝试，键盘在设备断电下恢复切换设备能力。

至此初步原因确认，在有线供电下，无论供电侧是否为真实开机设备，官方键盘主控的逻辑会阻塞切换连接切换功能。可以简单的理解为下面的模型：

![](https://static.chiphell.com/forum/202611/04/172503mx1n9wqk998i8gjz.png)

但是关闭外设供电也同样会影响一些设备唤醒的功能。

## 官方固件 & AI 时代和第三方方案

截止目前，官网最新固件仍然无法解决这个问题。大约 1 年前我曾经在小红书之类的社交媒体上留言。我记得当时官方账号和评论有大量互动，但是我的问题截止 1 年后的今天没有反馈。在该键盘的合作发行商`in皂设`前 2 天v2版本的小红书预热贴的评论区，我也同样提及该问题，当然依然是冷处理。

这个问题真的很难解吗？难道主控芯片接收到的信号，就无法判断键盘与主机的连接状态从而实现自动切换吗？

得力于 AI，找到一个名为 scholzri 的用户开源了自己对这把键盘的逆向：
<https://github.com/scholzri/rainy75-zmk> 是一个开源代码对 rainy75 主控 PCB 做了逆向分析和改造，其中有有些逻辑挺耐人寻味的，以下为 G*t 的分析：

> Telink TLSR9511B（B91）没有独立的 USB VBUS 检测引脚。
> 开源项目作者甚至专门为此修改了 ZMK
>
> - 读取 USB 是否完成 HID 配置。
> - 读取 USB 是否处于 Suspend。
> - 根据当前输出模式（USB/BLE）判断是否应该继续保持唤醒。
> - 对于已经切换到 BLE、USB 总线又长期挂起的情况，允许键盘进入低功耗状态。
> - 对 USB Suspend 后的异常恢复做了额外处理。
>
> 其中最有意思的是，它甚至设置了 60 秒的 BLE 宽限期，避免把一个暂时挂起、但未来可能需要 USB 唤醒的主机误判成已经断开。

当然项目本身有一定门槛，即便在agent时代，依然需要单独准备对应的环境确认。仓库作者明确表示需要Linux辅助调试，很显然不算友好。

## 总结

LZ之所以当初购买这把 rainy75 v1，就是欣赏其在相关圈子里的口碑和综合素质，但真的走近接触，有些问题很显然没有那么简单。
其实有问题不算可怕，特别在 AI 时代有些问题其实解决成本可以很廉价，但是一个品牌如果丧失了倾听和担当，走不了多远。
